--------------------------------------------------------------------------------
1. WHAT IS THIS PROJECT? (IN 3 SIMPLE SENTENCES)
--------------------------------------------------------------------------------
This project is a web-based Single-Server Queueing Simulator for a Petrol Pump.
It calculates how long cars wait in line, how long they spend at the pump,
and how busy the pump is under 3 classical single-server queueing models.
Users and teachers can enter custom arrival and service parameters directly to
test any scenario.

--------------------------------------------------------------------------------
2. HOW THE SOFTWARE WORKS (SIMPLE ARCHITECTURE)
--------------------------------------------------------------------------------
The software has 3 clean parts:

1. FRONTEND (User Interface):
   - index.html & style.css: Modern dark-themed dashboard inspired by an
     illuminated petrol station at night.
   - app.js: Reads user-entered parameters (arrival time/rate, service time/rate,
     and standard deviations) and calculates results via backend REST API or
     client-side engine.

2. BACKEND (Express Server):
   - server.js: A lightweight Node.js Express server that serves the UI and
     dispatches calculation requests to the queueing engine via REST API.

3. CALCULATION ENGINE (The Math):
   - queueModels.js: Pure mathematical engine for single-server models (M/M/1,
     M/G/1, and G/G/1) providing step-by-step formula substitutions.

--------------------------------------------------------------------------------
3. DATA INPUT & OPERATIONAL DYNAMICS
--------------------------------------------------------------------------------
The user/teacher can enter values in seconds, minutes, or hours, either as
"Mean Time" or as "Rate" (vehicles per time unit):

- Arrival Input : Mean inter-arrival time (or arrival rate λ)
- Service Input : Mean service time (or service rate μ)
- Variations    : Standard deviation for arrival (G/G/1) and service (M/G/1, G/G/1)

EXAMPLE TEST CASE TO DEMONSTRATE TO YOUR TEACHER:
- Enter Arrival Mean Time = 45 seconds (λ = 1.33 cars/minute)
- Enter Service Mean Time = 30 seconds (μ = 2.00 cars/minute)
- Result:
  * Utilization: ρ = 30 / 45 = 0.6667 (66.67% busy)
  * System is stable (ρ < 1.0) and queue operates smoothly.

BOTTLENECK TEST CASE (SHOWING SATURATION):
- If you enter Arrival Mean Time = 40 seconds and Service Mean Time = 39 seconds:
  * ρ = 39 / 40 = 0.975 (97.5% utilization)
  * Notice how queue length (Lq) and waiting time (Wq) shoot up dramatically!

--------------------------------------------------------------------------------
4. KEY SYMBOLS YOU MUST KNOW (TEACHER VIVA CHEAT-SHEET)
--------------------------------------------------------------------------------
Symbol   What it Means                  In Plain English
--------------------------------------------------------------------------------
lambda   Arrival Rate                   How many cars arrive per unit time (1 / Mean Arrival)
mu       Service Rate                   How many cars the pump can fuel per unit time (1 / Mean Service)
rho      Pump Utilization               How busy the pump is: rho = lambda / mu (must be < 1.0)
Lq       Queue Length                   Average number of cars WAITING in line
L        System Length                  Average total number of cars at the station
Wq       Waiting Time in Queue          Average time a driver waits in line
W        Total Time in System           Waiting time + Fueling time: W = Wq + (1 / mu)
P0       Empty Probability              Chance the station has zero cars: P0 = 1 - rho

STABILITY RULE:
"rho must be strictly LESS than 1 (rho < 1). If rho >= 1, cars arrive faster
than the pump can fuel them, meaning the queue will grow indefinitely."

LITTLE'S LAW:
- L  = lambda * W   (Total cars = Arrival rate * Total time in system)
- Lq = lambda * Wq  (Cars waiting = Arrival rate * Waiting time in line)
- W  = Wq + (1 / mu) (Total time = Waiting time + Service time)

--------------------------------------------------------------------------------
5. THE 3 SINGLE-SERVER QUEUE MODELS
--------------------------------------------------------------------------------

MODEL 1: M/M/1 (Single Server, Exponential Arrival & Service)
- Meaning: 1 pump. Both vehicle arrivals and service durations follow memoryless
  exponential distributions (Poisson process).
- Formula:
    Lq = rho^2 / (1 - rho)
    P0 = 1 - rho
- When to use: When arrival and service times are purely random.

MODEL 2: M/G/1 (Single Server, General Service Distribution with Variance)
- Meaning: 1 pump. Arrivals are Poisson, but service time has an arbitrary
  distribution with a custom variance (sigma^2).
- Formula (Pollaczek-Khinchine Formula):
    Lq = [ lambda^2 * sigma^2 + rho^2 ] / [ 2 * (1 - rho) ]
- Key Takeaway: Proves mathematically that higher service time variation (sigma)
  directly creates longer queues, even if the average service speed is the same.

MODEL 3: G/G/1 (Single Server, General Arrival & General Service)
- Meaning: 1 pump. Neither arrivals nor service are strictly exponential; both
  have their own custom mean and standard deviation entered by the user.
- Formula (Sakasegawa Single-Server Approximation):
    Ca^2 = (sigma_a / Mean_a)^2
    Cs^2 = (sigma_s / Mean_s)^2
    Wq ≈ [ rho / (1 - rho) ] * [ (Ca^2 + Cs^2) / 2 ] * (1 / mu)
    Lq = lambda * Wq
- When to use: When testing realistic models using custom standard deviations.

6. TOP 5 VIVA QUESTIONS & DIRECT ANSWERS
--------------------------------------------------------------------------------

Q1: What does Kendall's Notation mean in M/M/1, M/G/1, and G/G/1?
Answer:
"The 1st letter represents arrival distribution ('M' = Markovian/Poisson, 'G' = General).
The 2nd letter represents service distribution ('M' = Exponential, 'G' = General).
The number '1' means a single server (one petrol pump)."

Q2: What is 'rho' (Utilization) and why must it be below 1?
Answer:
"rho = lambda / mu represents the fraction of time the pump is busy.
It must be strictly less than 1 (rho < 1) for the queue to reach steady-state.
If rho >= 1, cars arrive faster than they are serviced, causing infinite queue growth."

Q3: What is Little's Law?
Answer:
"Little's Law states L = lambda * W and Lq = lambda * Wq. It directly connects
the average number of cars in the system to arrival rate and waiting time."

Q4: What is the Pollaczek-Khinchine formula in M/G/1?
Answer:
"It calculates queue length for general service times:
Lq = (lambda^2 * sigma^2 + rho^2) / [2 * (1 - rho)].
It shows that variance in fueling times (sigma^2) directly increases queue delay."

Q5: What happens when arrival rate gets very close to service rate?
Answer:
"As rho approaches 1.0, the denominator (1 - rho) approaches 0.
This causes queue length (Lq) and waiting time (Wq) to increase exponentially,
demonstrating the bottleneck effect in single-server systems."
